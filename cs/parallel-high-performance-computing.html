并行与高性能计算

从多核 CPU 到 GPU 集群，覆盖 OpenMP、MPI、CUDA 与 Python 并行。 并行计算是大规模科学计算的加速关键—— 有限元求解、地震波传播模拟、PSHA 蒙特卡洛、 机器学习训练，都依赖并行技术把"不可行"变为"可行"。

OpenMP MPI GPU 科学计算

§引言

并行计算研究同时使用多个计算资源求解问题。 高性能计算（HPC）是把并行计算、算法优化、 硬件选型等结合起来，追求极致性能的工程实践。

为什么需要并行？因为单核性能已接近物理极限：

  • 时钟频率自 2005 年起停留在 3~5 GHz，摩尔定律放缓。
  • 内存带宽、功耗、散热都限制了单核性能。
  • 硬件厂商转向多核、众核、异构计算。

工程计算中，并行是"分水岭"：

问题串行并行加速
有限元求解（10⁷ 自由度） 数小时 数分钟（64 核） 50~100 倍
地震波场模拟（区域尺度） 数天 数小时（GPU） 100~500 倍
PSHA 蒙特卡洛（10⁸ 样本） 数周 数小时（集群） 100~1000 倍
CNN 训练（STEAD 数据集） 数周 数小时（GPU） 50~200 倍
反应谱批量计算（10⁵ 条记录） 数天 数分钟（多核） 50~100 倍
波形互相关（台阵数据） 数天 数小时（GPU） 100 倍

对地震工程师来说，并行计算的三大价值：

  • 突破规模上限：把"算不动"的问题变成"算得动"。
  • 缩短迭代周期：从"过夜跑"变成"边写边看结果"。
  • 支持实时应用：地震预警需要毫秒级响应。

这份笔记按"基础 $\to$ 硬件 $\to$ OpenMP $\to$ MPI $\to$ GPU $\to$ Python $\to$ 算法 $\to$ 优化 $\to$ 应用" 的顺序梳理，每一节都尽量落到工程语境上。

并行可以在多个层次实现：

按指令流与数据流的组合，计算架构分为四类：

类别全称说明代表

Amdahl 定律

设程序中可并行部分占比例 $p$，串行部分占 $1-p$， 使用 $N$ 个处理器时的理论加速比为：

$$ S(N) = \frac{1}{(1 - p) + p / N} $$

当 $N \to \infty$ 时，$S \to 1/(1-p)$。 串行部分是并行的天花板。

举例：

可并行比例 $p$N = 4N = 16N = 64N → ∞
0.90 3.08 6.40 8.77 10.0
0.95 3.48 9.14 15.4 20.0
0.99 3.88 13.9 39.3 100
0.999 3.99 15.8 61.5 1000

要获得 100 倍以上的加速，可并行比例必须超过 99%。 这就是为什么优化串行部分比增加核心更重要。

Gustafson 定律

Amdahl 定律假设问题规模固定。 但实际中，更多资源往往用于解决更大问题。 Gustafson 定律描述这种弱扩展（weak scaling）：

$$ S(N) = N - \alpha (N - 1) $$

其中 $\alpha$ 是串行部分的比例。 当问题规模随核心数增加时，加速比可以接近 $N$。

性能度量

  • 强扩展（strong scaling）：问题规模固定，增加核心数。受 Amdahl 定律限制。
  • 弱扩展（weak scaling）：问题规模随核心数增加。接近线性加速。
  • 并行效率：$E = S(N) / N$，理想情况为 1。
  • 加速比：$S(N) = T_1 / T_N$。

实际中，加速比通常在 $N/2$ 到 $N \times 0.9$ 之间。 如果加速比低于 $N/2$，说明存在明显瓶颈。

💡

Amdahl 定律的启示： 假设一个程序 95% 可并行、5% 串行， 即使使用 1000 个核心，最大加速比也只有 20 倍。 要真正获得大规模加速，必须： ① 减小串行部分（算法重构）； ② 让问题规模随资源增长（弱扩展）； ③ 消除通信、同步、I/O 等隐藏串行开销。 这就是 HPC 工程师日常工作的核心。

02并行硬件架构

共享内存架构（UMA / NUMA）

多个处理器共享同一物理内存：

  • UMA（Uniform Memory Access）：所有核心访问内存延迟相同。
  • NUMA（Non-Uniform Memory Access）：内存分块，就近访问快。

NUMA 是现代多路服务器的标准架构。 编程时需注意内存亲和性（memory affinity）， 尽量让线程访问本地内存。

分布式内存架构

每个节点有独立内存，通过高速网络连接：

  • 集群：以太网、InfiniBand、Omni-Path。
  • MPP：大规模并行处理，专用架构。
  • 云 HPC：AWS、Azure、阿里云的高性能实例。

节点间通信带宽对比：

互连带宽延迟典型用途
以太网 10GbE 1.25 GB/s ~50 μs 通用集群
以太网 100GbE 12.5 GB/s ~10 μs 高性能集群
InfiniBand HDR 25 GB/s ~1 μs HPC 集群
InfiniBand NDR 50 GB/s ~0.6 μs 顶级超算

GPU 架构

GPU 有数千个简单核心，适合数据并行：

对比CPUGPU
核心数 8~128 1000~20000
单核性能 高 低
频率 3~5 GHz 1~2 GHz
内存带宽 50~500 GB/s 1000~3000 GB/s
适用 逻辑复杂、串行 数据并行、浮点密集
编程 简单 复杂（CUDA / OpenACC）

GPU 的优势来自吞吐量而非延迟。 单个操作延迟高，但同时执行数千个操作。

异构计算

现代超算通常是 CPU + GPU 的异构系统：

  • CPU：控制流、复杂逻辑、I/O。
  • GPU：数据并行、密集计算。
  • 互连：PCIe、NVLink（GPU 间高速通信）。

Summit、Fugaku、Frontier 等顶级超算都是异构架构。 前端处理、任务调度、结果分析在 CPU， 计算密集型核心在 GPU。

典型硬件配置

级别配置典型算力适用
笔记本 4~8 核 CPU ~50 GFLOPS 开发、小规模
工作站 16~64 核 + 1 GPU ~10 TFLOPS 中等规模
单节点服务器 64~128 核 + 4 GPU ~100 TFLOPS 大规模
集群（100 节点） 100 × 128 核 + 400 GPU ~10 PFLOPS 区域尺度模拟
超算 数千节点 + 数万 GPU ~100 PFLOPS~1 EFLOPS 前沿研究
💡

如何选择并行硬件： ① 问题规模小：笔记本或工作站即可； ② 中等规模、易并行：多核 CPU + OpenMP； ③ 大规模、域分解：集群 + MPI； ④ 数据并行密集：GPU + CUDA； ⑤ 混合：MPI（节点间）+ OpenMP（节点内）+ GPU（加速核）。 地震学中，区域波场模拟、机器学习训练适合 GPU； 有限元求解、PSHA 蒙特卡洛适合 CPU 集群。

03共享内存与 OpenMP

OpenMP 简介

OpenMP 是基于指令（pragma）的共享内存并行编程模型， 支持 C、C++、Fortran。 只需在循环前加一行 #pragma omp parallel for， 编译器自动并行化。

Hello World

hello_openmp.c C 
#include <stdio.h>
#include <omp.h>

int main() {
    #pragma omp parallel
    {
        int tid = omp_get_thread_num();
        int nthreads = omp_get_num_threads();
        printf("Hello from thread %d of %d\n", tid, nthreads);
    }
    return 0;
}

编译与运行：

gcc -fopenmp hello_openmp.c -o hello
OMP_NUM_THREADS=4 ./hello

# 输出示例：
# Hello from thread 0 of 4
# Hello from thread 1 of 4
# Hello from thread 2 of 4
# Hello from thread 3 of 4

并行 for 循环

parallel_for.c C 
#include <stdio.h>
#include <stdlib.h>
#include <omp.h>

int main() {
    const int n = 100000000;
    double *a = malloc(n * sizeof(double));
    double *b = malloc(n * sizeof(double));
    double *c = malloc(n * sizeof(double));

    // 初始化
    for (int i = 0; i < n; i++) {
        a[i] = 1.0;
        b[i] = 2.0;
    }

    // 并行向量加法
    double t0 = omp_get_wtime();

    #pragma omp parallel for
    for (int i = 0; i < n; i++) {
        c[i] = a[i] + b[i];
    }

    double t1 = omp_get_wtime();
    printf("Elapsed: %.4f s\n", t1 - t0);

    free(a); free(b); free(c);
    return 0;
}

归约示例

reduction.c C 
#include <stdio.h>
#include <omp.h>

int main() {
    const int n = 100000000;
    double sum = 0.0;

    // 计算 1/i² 的和
    #pragma omp parallel for reduction(+:sum)
    for (int i = 1; i <= n; i++) {
        sum += 1.0 / ((double)i * i);
    }

    // 理论值 π²/6 ≈ 1.644934
    printf("Sum = %.10f\n", sum);
    printf("Theory (π²/6) = %.10f\n", 1.6449340668482264);
    return 0;
}

reduction(+:sum) 让每个线程有独立副本， 最后自动求和。避免竞争条件。

策略说明适用

dynamic 谁空闲谁拿下一块 工作量不均
guided 动态、块大小递减 中等不均
auto 编译器决定 通用

数据竞争与临界区

critical.c C 
#include <stdio.h>
#include <omp.h>

int main() {
    double sum = 0.0;
    const int n = 10000000;

    // 错误：数据竞争
    // #pragma omp parallel for
    // for (int i = 0; i < n; i++) sum += 1.0;  // 结果不确定

    // 正确方式 1：reduction
    #pragma omp parallel for reduction(+:sum)
    for (int i = 0; i < n; i++) sum += 1.0;

    // 正确方式 2：atomic
    double sum2 = 0.0;
    #pragma omp parallel for
    for (int i = 0; i < n; i++) {
        #pragma omp atomic
        sum2 += 1.0;
    }

    // 正确方式 3：critical（较慢）
    double sum3 = 0.0;
    #pragma omp parallel for
    for (int i = 0; i < n; i++) {
        #pragma omp critical
        { sum3 += 1.0; }
    }

    printf("reduction: %.0f\n", sum);
    printf("atomic:    %.0f\n", sum2);
    printf("critical:  %.0f\n", sum3);
    return 0;
}

推荐顺序：reduction > atomic > critical。 critical 会串行化临界区，性能最差。

04消息传递与 MPI

MPI 简介

MPI（Message Passing Interface）是分布式内存并行的标准。 多个进程各自有独立内存，通过消息传递协作。

MPI 的核心概念：

  • Communicator：进程组 + 通信上下文。
  • Rank：进程在组内的编号（0 到 N-1）。
  • Point-to-point：两个进程通信。
  • Collective：所有进程参与的通信。

Hello World

hello_mpi.c C 
#include <stdio.h>
#include <mpi.h>

int main(int argc, char **argv) {
    MPI_Init(&argc, &argv);

    int rank, size;
    MPI_Comm_rank(MPI_COMM_WORLD, &rank);
    MPI_Comm_size(MPI_COMM_WORLD, &size);

    char hostname[256];
    gethostname(hostname, sizeof(hostname));

    printf("Rank %d of %d on %s\n", rank, size, hostname);

    MPI_Finalize();
    return 0;
}

点对点通信

pingpong.c C 
#include <stdio.h>
#include <mpi.h>

int main(int argc, char **argv) {
    MPI_Init(&argc, &argv);

    int rank;
    MPI_Comm_rank(MPI_COMM_WORLD, &rank);

    const int N = 1000000;
    double *buf = malloc(N * sizeof(double));

    if (rank == 0) {
        // 发送
        for (int i = 0; i < N; i++) buf[i] = 1.0;
        MPI_Send(buf, N, MPI_DOUBLE, 1, 0, MPI_COMM_WORLD);

        // 接收回复
        MPI_Recv(buf, N, MPI_DOUBLE, 1, 1, MPI_COMM_WORLD, MPI_STATUS_IGNORE);
        printf("Rank 0 received reply, buf[0] = %.1f\n", buf[0]);
    } else if (rank == 1) {
        MPI_Recv(buf, N, MPI_DOUBLE, 0, 0, MPI_COMM_WORLD, MPI_STATUS_IGNORE);
        printf("Rank 1 received data, buf[0] = %.1f\n", buf[0]);

        // 处理并回复
        for (int i = 0; i < N; i++) buf[i] *= 2.0;
        MPI_Send(buf, N, MPI_DOUBLE, 0, 1, MPI_COMM_WORLD);
    }

    free(buf);
    MPI_Finalize();
    return 0;
}

并行求和示例

parallel_sum.c C 
#include <stdio.h>
#include <stdlib.h>
#include <mpi.h>

int main(int argc, char **argv) {
    MPI_Init(&argc, &argv);

    int rank, size;
    MPI_Comm_rank(MPI_COMM_WORLD, &rank);
    MPI_Comm_size(MPI_COMM_WORLD, &size);

    const long N = 1000000000L;

    // 计算本进程负责的范围
    long chunk = N / size;
    long start = rank * chunk;
    long end = (rank == size - 1) ? N : start + chunk;

    double local_sum = 0.0;
    for (long i = start + 1; i <= end; i++) {
        local_sum += 1.0 / ((double)i * i);
    }

    // 归约到 rank 0
    double global_sum = 0.0;
    MPI_Reduce(&local_sum, &global_sum, 1, MPI_DOUBLE,
               MPI_SUM, 0, MPI_COMM_WORLD);

    if (rank == 0) {
        printf("Sum = %.10f\n", global_sum);
        printf("Theory (π²/6) = %.10f\n", 1.6449340668482264);
    }

    MPI_Finalize();
    return 0;
}

并行效率分析

并行计算的总时间由三部分组成：

$$ T_{\text{total}} = T_{\text{compute}} + T_{\text{comm}} + T_{\text{sync}} $$

其中：

  • $T_{\text{compute}}$：计算时间，随进程数下降。
  • $T_{\text{comm}}$：通信时间，随进程数上升。
  • $T_{\text{sync}}$：同步开销，随进程数上升。

当进程数很大时，通信与同步成为瓶颈。 这就是弱扩展曲线在大规模时偏离线性的原因。

MPI 使用建议

  • 尽量减少通信次数：批量发送比多次小消息高效。
  • 使用非阻塞通信：MPI_Isend、MPI_Irecv，通信与计算重叠。
  • 使用集合通信：比点对点更快（内部优化）。
  • 避免同步开销：减少 MPI_Barrier 调用。
  • 负载均衡：让各进程工作量相近。
  • 通信与计算重叠：用非阻塞通信隐藏通信延迟。
💡

MPI 与 OpenMP 的混合编程： 现代 HPC 的标准模式是 MPI + OpenMP： ① MPI 负责节点间通信（粗粒度）； ② OpenMP 负责节点内多线程（细粒度）； ③ GPU 负责计算密集型核心（如矩阵运算）。 这种"三层并行"能充分利用各级并行资源， 是地震波传播模拟、有限元求解的常用架构。

05GPU 与 CUDA

CUDA 编程模型

CUDA 是 NVIDIA 的 GPU 编程平台。 核心概念：

  • Thread：最小执行单元。
  • Warp：32 个线程一组，同时执行同一条指令。
  • Block：线程块，可共享共享内存。
  • Grid：线程块集合，对应一次核函数调用。

Hello GPU

hello_gpu.cu C 
#include <stdio.h>

__global__ void hello_kernel() {
    int tid = blockIdx.x * blockDim.x + threadIdx.x;
    printf("Hello from thread %d\n", tid);
}

int main() {
    // 启动 4 个 block，每个 8 个线程
    hello_kernel<<<4, 8>>>();
    cudaDeviceSynchronize();
    return 0;
}

编译与运行：

nvcc hello_gpu.cu -o hello_gpu
./hello_gpu

向量加法

vector_add.cu C 
#include <stdio.h>
#include <cuda_runtime.h>

__global__ void vec_add(const float *a, const float *b,
                        float *c, int n) {
    int i = blockIdx.x * blockDim.x + threadIdx.x;
    if (i < n) {
        c[i] = a[i] + b[i];
    }
}

int main() {
    const int n = 10000000;
    size_t bytes = n * sizeof(float);

    // 分配主机内存
    float *h_a = (float*)malloc(bytes);
    float *h_b = (float*)malloc(bytes);
    float *h_c = (float*)malloc(bytes);

    for (int i = 0; i < n; i++) {
        h_a[i] = 1.0f;
        h_b[i] = 2.0f;
    }

    // 分配设备内存
    float *d_a, *d_b, *d_c;
    cudaMalloc(&d_a, bytes);
    cudaMalloc(&d_b, bytes);
    cudaMalloc(&d_c, bytes);

    // 拷贝到设备
    cudaMemcpy(d_a, h_a, bytes, cudaMemcpyHostToDevice);
    cudaMemcpy(d_b, h_b, bytes, cudaMemcpyHostToDevice);

    // 启动核函数
    int threads = 256;
    int blocks = (n + threads - 1) / threads;
    vec_add<<<blocks, threads>>>(d_a, d_b, d_c, n);

    // 拷贝回主机
    cudaMemcpy(h_c, d_c, bytes, cudaMemcpyDeviceToHost);

    // 验证
    printf("c[0] = %.1f, c[n-1] = %.1f\n", h_c[0], h_c[n-1]);

    // 释放
    cudaFree(d_a); cudaFree(d_b); cudaFree(d_c);
    free(h_a); free(h_b); free(h_c);
    return 0;
}

GPU 的适用与不适用

场景适合 GPU原因
矩阵乘法 非常适合 数据并行、密集计算
卷积 非常适合 规则结构、可并行
FFT 适合 分治 + 并行
蒙特卡洛 非常适合 独立样本、无依赖
稀疏线性求解 部分适合 不规则访问，需优化
图算法 较难 不规则、随机访问
动态规划 较难 有依赖、串行

GPU 的"起飞"门槛：数据量足够大、计算足够密集、 数据传输开销可接受。否则 CPU 反而更快。

06Python 并行

GIL 与并行策略

Python 的全局解释器锁（GIL）限制了多线程的并行能力：

  • CPU 密集型：GIL 导致多线程无法并行，需要多进程。
  • I/O 密集型：GIL 在 I/O 时释放，多线程有效。
  • NumPy 运算：底层 C 代码释放 GIL，多线程可加速。
场景推荐方案理由
CPU 密集、无共享状态 multiprocessing 绕过 GIL
I/O 密集 threading / asyncio I/O 时释放 GIL
NumPy 数组运算 向量化 + 多线程 BLAS 底层并行
大规模数据管道 Dask / Ray 分布式任务调度
GPU 计算 CuPy / PyTorch GPU 并行
循环密集 Numba / Cython JIT 编译

multiprocessing_demo.py Python 
"""
用 multiprocessing 并行计算反应谱。
"""
import time
import numpy as np
from multiprocessing import Pool


def compute_sa(args):
    """计算单个周期的 Sa（CPU 密集）"""
    T, acc, dt, zeta = args
    # 简化的单自由度响应计算
    omega = 2 * np.pi / T
    n = len(acc)
    u = np.zeros(n)
    v = np.zeros(n)
    a = np.zeros(n)
    a[0] = -acc[0] - 2 * zeta * omega * v[0] - omega**2 * u[0]
    beta, gamma = 0.25, 0.5
    c = 2 * zeta * omega
    k = omega**2
    K_eff = k + gamma / (beta * dt) * c + 1.0 / (beta * dt**2)
    for i in range(n - 1):
        P_eff = (-acc[i + 1]
                 + 1.0 / (beta * dt**2) * u[i]
                 + 1.0 / (beta * dt) * v[i]
                 + (1.0 / (2 * beta) - 1) * a[i]
                 + c * (gamma / (beta * dt) * u[i]
                        + (gamma / beta - 1) * v[i]
                        + dt * (gamma / (2 * beta) - 1) * a[i]))
        u[i + 1] = P_eff / K_eff
        v[i + 1] = (gamma / (beta * dt) * (u[i + 1] - u[i])
                    - (gamma / beta - 1) * v[i]
                    - dt * (gamma / (2 * beta) - 1) * a[i])
        a[i + 1] = (1.0 / (beta * dt**2) * (u[i + 1] - u[i])
                    - 1.0 / (beta * dt) * v[i]
                    - (1.0 / (2 * beta) - 1) * a[i])
    return T, np.max(np.abs(a + acc))


if __name__ == "__main__":
    # 生成地震动
    rng = np.random.default_rng(42)
    dt = 0.01
    t = np.arange(0, 60, dt)
    acc = np.zeros_like(t)
    for f, amp in [(0.5, 0.5), (1.5, 1.0), (3.0, 0.8), (5.0, 0.3)]:
        acc += amp * np.sin(2 * np.pi * f * t + rng.uniform(0, 6.28))
    acc *= np.exp(-((t - 15) ** 2) / (2 * 8**2))

    periods = np.logspace(np.log10(0.05), np.log10(5.0), 100)
    zeta = 0.05

    # ---- 串行 ----
    t0 = time.perf_counter()
    Sa_serial = [compute_sa((T, acc, dt, zeta))[1] for T in periods]
    t_serial = time.perf_counter() - t0

    # ---- 并行 ----
    args = [(T, acc, dt, zeta) for T in periods]

    t0 = time.perf_counter()
    with Pool() as pool:
        results = pool.map(compute_sa, args)
    Sa_parallel = [r[1] for r in results]
    t_parallel = time.perf_counter() - t0

    print(f"串行: {t_serial:.3f} s")
    print(f"并行: {t_parallel:.3f} s")
    print(f"加速比: {t_serial / t_parallel:.2f} 倍")
    print(f"CPU 核心数: {__import__('os').cpu_count()}")

    # 验证
    assert np.allclose(Sa_serial, Sa_parallel)
    print("✓ 结果一致")

"""
用 Numba 的 parallel=True 自动并行化。
安装：pip install numba
"""
import time
import numpy as np

try:
    from numba import njit, prange
    HAS_NUMBA = True
except ImportError:
    HAS_NUMBA = False


if HAS_NUMBA:
    @njit(parallel=True)
    def parallel_sum(arr):
        """自动并行化的求和"""
        n = len(arr)
        result = np.zeros(n, dtype=np.float64)
        for i in prange(n):
            result[i] = arr[i] * arr[i]
        return result.sum()

    @njit
    def serial_sum(arr):
        """串行求和"""
        s = 0.0
        for i in range(len(arr)):
            s += arr[i] * arr[i]
        return s

    @njit(parallel=True)
    def parallel_sa_batch(acc, dt, periods, zeta):
        """批量计算反应谱（并行）"""
        n_periods = len(periods)
        Sa = np.zeros(n_periods)
        for ip in prange(n_periods):
            T = periods[ip]
            omega = 2 * np.pi / T
            beta, gamma = 0.25, 0.5
            c = 2 * zeta * omega
            k = omega**2
            K_eff = k + gamma / (beta * dt) * c + 1.0 / (beta * dt**2)

            u = 0.0
            v = 0.0
            a = -acc[0] - 2 * zeta * omega * v - omega**2 * u
            a_max = 0.0

            for i in range(len(acc) - 1):
                P_eff = (-acc[i + 1]
                         + 1.0 / (beta * dt**2) * u
                         + 1.0 / (beta * dt) * v
                         + (1.0 / (2 * beta) - 1) * a
                         + c * (gamma / (beta * dt) * u
                                + (gamma / beta - 1) * v
                                + dt * (gamma / (2 * beta) - 1) * a))
                u_new = P_eff / K_eff
                v = (gamma / (beta * dt) * (u_new - u)
                     - (gamma / beta - 1) * v
                     - dt * (gamma / (2 * beta) - 1) * a)
                a = (1.0 / (beta * dt**2) * (u_new - u)
                     - 1.0 / (beta * dt) * v
                     - (1.0 / (2 * beta) - 1) * a)
                u = u_new
                a_abs = abs(a + acc[i + 1])
                if a_abs > a_max:
                    a_max = a_abs
            Sa[ip] = a_max
        return Sa

    if __name__ == "__main__":
        # 生成地震动
        rng = np.random.default_rng(42)
        dt = 0.01
        t = np.arange(0, 60, dt)
        acc = np.zeros_like(t)
        for f, amp in [(0.5, 0.5), (1.5, 1.0), (3.0, 0.8)]:
            acc += amp * np.sin(2 * np.pi * f * t + rng.uniform(0, 6.28))
        acc *= np.exp(-((t - 15) ** 2) / (2 * 8**2))

        periods = np.logspace(np.log10(0.05), np.log10(5.0), 200)

        # 预热
        _ = parallel_sa_batch(acc[:1000], dt, periods[:5], 0.05)

        t0 = time.perf_counter()
        Sa = parallel_sa_batch(acc, dt, periods, 0.05)
        elapsed = time.perf_counter() - t0

        print(f"计算 {len(periods)} 个周期的反应谱")
        print(f"耗时: {elapsed:.3f} s")
        print(f"PGA = {Sa[0]:.4f}")
else:
    print("未安装 Numba，仅展示代码结构。")
    print()

    print("  from numba import njit, prange")

07并行算法设计

分解策略

策略说明适用
数据分解 把数据分给各进程 数组运算、PDE 求解
任务分解 把任务分给各进程 独立任务、蒙特卡洛
流水线 按阶段分给不同进程 信号处理链

域分解示例

把计算域分成 $P$ 个子域，每个进程负责一个： 

┌────┬────┬────┬────┐
│ P0 │ P1 │ P2 │ P3 │
│    │    │    │    │
├────┼────┼────┼────┤
│ P4 │ P5 │ P6 │ P7 │
│    │    │    │    │
└────┴────┴────┴────┘

相邻子域之间需要交换边界数据（halo exchange）。 这是有限差分、有限元并行的核心。

负载均衡

并行效率取决于各进程的工作量是否相近：

  • 静态划分：预先平均分配，适用于规则问题。
  • 动态划分：运行时分配，适用于不规则问题。
  • 空间填充曲线：Hilbert、Morton 曲线， 把多维空间映射到一维，实现负载均衡。
  • 图划分：METIS、ParMETIS，用于非结构网格。

减少通信

策略说明效果
增大粒度 每次通信传更多数据 减少通信次数
重叠通信与计算 非阻塞通信 + 计算 隐藏通信延迟
减少同步 少用 barrier 减少等待
局部化 让计算尽可能本地 减少远端访问
拓扑优化 进程映射到物理拓扑 减少跳数

并行复杂度分析

并行算法的总时间：

$$ T_p = \frac{W}{P} + T_{\text{comm}} + T_{\text{sync}} $$

其中 $W$ 是总工作量，$P$ 是进程数。 通信时间通常随 $P$ 增加：

$$ T_{\text{comm}} = \alpha + \beta m $$

其中 $\alpha$ 是延迟，$\beta$ 是单位数据传输时间，$m$ 是消息大小。 当 $P$ 很大时，$W/P$ 变小，而 $T_{\text{comm}}$ 不变或增大， 导致并行效率下降。

这就是为什么弱扩展（问题规模随 $P$ 增大）比强扩展 （问题规模固定）更容易获得高效。

Python 示例：域分解

domain_decomp.py Python 
"""
一维域分解示例：并行求解热传导方程。
"""
import numpy as np
from mpi4py import MPI


def heat_1d_domain_decomp(n_global=1000, n_steps=1000, alpha=0.01):
    """一维热传导方程的域分解并行求解"""
    comm = MPI.COMM_WORLD
    rank = comm.Get_rank()
    size = comm.Get_size()

    # 每个进程负责的局部大小
    n_local = n_global // size
    dx = 1.0 / (n_global - 1)
    dt = 0.4 * dx**2 / alpha

    # 局部数组（含两侧 halo）
    u = np.zeros(n_local + 2)
    u_new = np.zeros(n_local + 2)

    # 初始条件：中间高温
    x_start = rank * n_local * dx
    x_local = x_start + np.arange(1, n_local + 1) * dx
    u[1:-1] = np.exp(-((x_local - 0.5)**2) / (2 * 0.1**2))

    # 相邻进程
    left = rank - 1 if rank > 0 else MPI.PROC_NULL
    right = rank + 1 if rank < size - 1 else MPI.PROC_NULL

    # 时间推进
    for step in range(n_steps):
        # 交换 halo
        send_left = u[1].copy()
        send_right = u[-2].copy()

        recv_left = np.zeros(1)
        recv_right = np.zeros(1)

        comm.Sendrecv(send_right, dest=right, recvbuf=recv_left, source=left)
        comm.Sendrecv(send_left, dest=left, recvbuf=recv_right, source=right)

        u[0] = recv_left[0]
        u[-1] = recv_right[0]

        # 更新内部点
        u_new[1:-1] = u[1:-1] + alpha * dt / dx**2 * (
            u[2:] - 2 * u[1:-1] + u[:-2]
        )

        # 边界条件（左右两端固定为 0）
        if rank == 0:
            u_new[1] = 0.0
        if rank == size - 1:
            u_new[-2] = 0.0

        u, u_new = u_new, u

    # 收集到 rank 0
    local_result = u[1:-1]
    all_results = comm.gather(local_result, root=0)

    if rank == 0:
        full = np.concatenate(all_results)
        print(f"总长度: {len(full)}")
        print(f"最大值: {full.max():.4f}")
        print(f"峰值位置: {np.argmax(full) * dx:.4f}")
    return None


if __name__ == "__main__":
    heat_1d_domain_decomp(n_global=1000, n_steps=500)

# GCC 优化选项

# -O3：最高优化级别

# -flto：链接时优化

⚠️

并行优化的常见误区： ① 一上来就并行——先优化串行算法， 一个 $O(n^2)$ 的算法并行后仍是 $O(n^2)$； ② 盲目增加核心——Amdahl 定律会惩罚你， 超过一定核心数后加速比不再提升； ③ 忽略内存带宽——很多 HPC 问题受内存带宽限制， 而非计算能力； ④ 忽视 I/O——读写数据可能占 80% 的时间； ⑤ 并行调试困难——先在小规模验证正确性， 再扩展到大规模。

PSHA 蒙特卡洛并行

psha_parallel.py Python 
"""
用 multiprocessing 并行化 PSHA 蒙特卡洛。
"""
import numpy as np
from multiprocessing import Pool
import time


def simulate_year(args):
    """模拟一年的最大 PGA"""
    seed, lambda_rate = args
    rng = np.random.default_rng(seed)

    n_event = rng.poisson(lambda_rate)
    if n_event == 0:
        return -10.0

    M = rng.uniform(4.5, 8.0, n_event)
    R = rng.uniform(10.0, 200.0, n_event)

    # GMPE
    ln_pga = (1.5 + 0.8 * M - 1.2 * np.log(R + 10)
              - 0.002 * R + rng.normal(0, 0.4, n_event))

    return float(ln_pga.max())


def psha_mc_serial(n_years, seed=42):
    """串行蒙特卡洛"""
    rng = np.random.default_rng(seed)
    results = []
    for i in range(n_years):
        s = int(rng.integers(0, 2**31))
        results.append(simulate_year((s, 0.1)))
    return np.array(results)


def psha_mc_parallel(n_years, n_workers=None, seed=42):
    """并行蒙特卡洛"""
    rng = np.random.default_rng(seed)
    tasks = [(int(rng.integers(0, 2**31)), 0.1) for _ in range(n_years)]

    with Pool(n_workers) as pool:
        results = pool.map(simulate_year, tasks)
    return np.array(results)


if __name__ == "__main__":
    n_years = 200_000

    # 串行
    t0 = time.perf_counter()
    r_serial = psha_mc_serial(n_years)
    t_serial = time.perf_counter() - t0

    # 并行
    t0 = time.perf_counter()
    r_parallel = psha_mc_parallel(n_years)
    t_parallel = time.perf_counter() - t0

    print(f"串行: {t_serial:.2f} s")
    print(f"并行: {t_parallel:.2f} s")
    print(f"加速比: {t_serial / t_parallel:.2f} 倍")

    # 统计
    for r, name in [(r_serial, "串行"), (r_parallel, "并行")]:
        n_no_event = np.sum(r < -5)
        print(f"\n{name}:")
        print(f"  无地震年份比例: {n_no_event / len(r):.4f}")
        print(f"  年均超越概率 (PGA > 0.1): {np.mean(r > np.log(0.1)):.6f}")

地震预警的低延迟并行

地震预警对延迟要求极高，并行策略不同于传统 HPC：

  • 流水线并行：数据接收、预处理、检测、定位、发布分阶段并行。
  • 数据并行：多台站同时处理，GPU 加速推理。
  • 低延迟通信：共享内存、RDMA、零拷贝。
  • 实时调度：优先级队列，确保关键任务及时处理。
  • 容错设计：单点故障不影响整体。

这类系统的瓶颈通常不是计算能力，而是端到端延迟—— 包括采集、传输、处理、发布的全链路。
